# Типы секретов и конфигурация бакета

Каждый секрет остаётся отдельной зашифрованной записью. JSON/YAML — представление
согласованного снимка бакета, а не дополнительная копия данных в хранилище.

## Типы

`string` (по умолчанию), `number`, `boolean`, `null`. Массивы и объекты не являются
значениями секретов. Строки `"true"`, `"00123"`, `"null"` не преобразуются автоматически.
Тип выбирается в админке или определяется типом аргумента типизированного метода SDK.

На wire значение остаётся **строкой**, а тип передаётся явно:

```json
{"bucket":"app","key":"Redis:Port","value":"6379","type":"number"}
```

`type` необязателен в secret.create/update/set; отсутствие означает `string`,
в том числе при обновлении. Для сохранения типа используйте типизированный метод
или передавайте type явно. secret.read/list и ответы записи возвращают type в metadata.
`bucket.read` возвращает `secrets` со строковыми представлениями и разреженный
словарь `types`: отсутствующий в types ключ означает string.

Числа — конечные JSON numbers в пределах возможностей IEEE 754 binary64;
целые ограничены ±9007199254740991. NaN, Infinity, ведущие нули, объекты и массивы
отклоняются. Дробные числа имеют обычную точность binary64; точные денежные значения
и большие целые храните строками. Сервер нормализует числа независимо от локали,
boolean в `true`/`false`, null в `null`. Строковый интерфейс и переменные окружения
получают именно эти строки. Пустая строка и null различаются.

Тип входит в AES-GCM AAD нового формата хранения 2. Существующий формат 1 читается
только как string; ротация перешифровывает его в формат 2. Смена типа требует
expectedRevision, меняет revision и записывается в аудит без значения секрета.
Лимит нового снимка — 1 МиБ UTF-8 JSON, включая словари secrets/types, до 4096 ключей.
Старые строковые записи не требуют миграции и не переименовываются.

## Вложенность

Плоский JSON сохраняет ключи буквально. Во вложенном JSON/YAML `:` разделяет уровни:
`Redis:Port` превращается в `{"Redis":{"Port":6379}}` для секрета типа number.
`\:` означает литеральное двоеточие в имени, `\\` — обратную косую черту.
Другие escape-последовательности, пустые сегменты и глубина больше 16 отклоняются.
Числовые сегменты остаются именами свойств: `Years:2026` создаёт объект, не массив.

Конфликт `Redis` + `Redis:Port` или одинаковых путей — ошибка независимо от порядка
обхода. Значения никогда не перезаписываются молча. Плоское представление остаётся
доступным для бакетов, которые не удовлетворяют правилам вложенности.

YAML формируется из того же дерева объектов и скаляров. Ключи и строковые значения
всегда заключены в двойные кавычки с JSON-экранированием (совместимо с YAML 1.2),
поэтому строки вроде `yes`, `00123` или даты остаются строками. Это экспорт
ограниченной модели, а не парсер произвольного YAML; комментарии, anchors и tags
не поддерживаются. Шаблоны, ссылки между бакетами, массивы и обратная запись
отредактированного документа не входят в эту реализацию.

## Админка

В бакете доступны Secrets и Configuration; последний сохраняется в URL как
`?view=configuration`. По умолчанию строится только структура по метаданным с
явными placeholders. Copy/Download недоступны в маскированном представлении.
Reveal all values вызывает существующий bucket.read (и его аудит); затем доступны
Flat JSON, Nested JSON и YAML, копирование и скачивание. При конфликте путей
копирование/скачивание блокируются; можно перейти к Flat JSON.

Hide values, смена страницы, refresh и выход очищают раскрытые значения.
Snapshot revision показывает версию прочитанного бакета. Повторное Reveal обновляет
снимок. Скачанный файл и системный clipboard уже находятся вне памяти страницы
и содержат секреты; браузер не может отозвать их при закрытии просмотра.

## Клиенты

| Клиент     | Строковое чтение              | Типизированное чтение и конфигурация                                                                           |
|------------|-------------------------------|----------------------------------------------------------------------------------------------------------------|
| C#         | ReadBucketAsync, Secret.Value | ReadTypedBucketAsync → JsonElement; Secret.GetTypedValue(); ReadConfigurationAsync<T>(bucket, JsonTypeInfo<T>) |
| Python     | read_bucket, read_secret      | read_typed_bucket, read_typed_secret, read_configuration → dict с native scalar                                |
| TypeScript | readBucket, readSecret        | readTypedBucket, readTypedSecret, readConfiguration → native scalar/object                                     |
| Go         | ReadBucket, Secret.Value      | ReadTypedBucket, Secret.TypedValue(), ReadConfiguration(ctx, bucket, &config)                                  |

Python/TypeScript принимают native string/number/bool/null в существующих методах
записи. C# имеет overload с JsonElement. Go — AddTypedSecret/UpdateTypedSecret/
SetTypedSecret с scalar-аргументом. Строковые методы C#/Go продолжают создавать string.

.NET IConfiguration получает строковые числа/boolean для штатного binding и null
для типа null. Его native-разделитель `:` и нечувствительность к регистру сохраняются;
коллизии регистра отклоняются. Для переносимого дерева с escape-последовательностями
и типизированного JSON binding используйте ReadConfigurationAsync<T>.

CLI читает значения из stdin/скрытого ввода; `secret add/update/set --type number`
задаёт тип. `bucket read --format json` сохраняет wire snapshot со строками и types.
`--format typed-json` выводит плоский типизированный объект, `nested-json` — вложенный,
`yaml` — вложенный YAML. `exec --bucket` всегда использует строковые значения;
null передаётся как строка `null`, а не удаляет переменную окружения.

Все раскрывающие конфигурацию операции используют существующие права bucket.read:
bucket:read + secret:read + secret:list. Форматы не создают отдельного обходного API.
