# Версионирование

Сервер, CLI и C#, Python, Go и TypeScript SDK выпускаются одним комплектом
с общей версией. Единственный источник версии релиза — Git-тег `vMAJOR.MINOR.PATCH`.
Версии отдельных компонентов перед релизом вручную не меняются.

- PATCH: совместимые исправления.
- MINOR: новые совместимые возможности.
- MAJOR: несовместимые изменения публичного API SDK, CLI или протокола.

Даже неизменившиеся компоненты получают версию комплекта. Версия wire-протокола
отдельная: `/api/v1` и поле `v: 1` не меняются при обычном выпуске.
Сейчас автоматизация принимает стабильные теги; prerelease-теги не поддерживаются.

## Локальная разработка

.NET использует `Directory.Build.props` с `0.0.0-dev`; CLI и TypeScript имеют такой же
маркер разработки. Python использует эквивалент PEP 440 `0.0.0.dev0`.
Это постоянные заглушки, а не независимые номера выпуска.

Сервер и CLI поддерживают `--version`, не открывая каталог данных и не требуя токен:

```powershell
dotnet run --project server/DarkVault.Server -- --version
go -C cli run . --version
```

Релизный вывод — `1.2.3+<commit SHA>`. Локальный CLI добавляет `.dirty`, если Go
обнаружил изменения при сборке. Для сборки без Git-метаданных SHA может отсутствовать
у .NET или обозначаться `unknown` у CLI.

## Выпуск

После отдельного разрешения на релиз создайте и отправьте тег `v1.2.3` на проверенный
коммит. CI проверяет все компоненты и собирает артефакты именно из этого тега.
Упаковка в CI запрещена из грязного checkout или при несовпадении тега с HEAD.

- Сервер: версия и SHA в assembly metadata.
- CLI: версия и SHA через Go linker flags.
- NuGet: общая версия пакетов, версия зависимости configuration → client, RepositoryCommit.
- Python: версия wheel/sdist и ссылка Source на точный коммит.
- TypeScript: версия npm-пакета и `gitHead`.
- Go: тег `clients/go/v1.2.3` на том же коммите и `release.json` в архиве исходников.

Go SDK v2+ требует суффикса `/v2` (либо соответствующего major) в module path
и обновления импортов; упаковка останавливается, если это не выполнено.

К релизу прикладываются 18 пакетов, `release.json` с версией, SHA, признаком грязной
локальной сборки и версией протокола, а также `SHA256SUMS` для всех 19 файлов.
`tools/check-release.py` сверяет точный набор файлов, контрольные суммы, версии
и метаданные пакетов. Для сервера проверяется версия DLL при упаковке и версия
в deps.json архива; CLI проверяется по встроенному маркеру версии и Git SHA из
`go version -m` без запуска чужой платформы.

Опубликованные теги и артефакты не заменяются. Повторное создание существующего
релиза или Go-тега завершится ошибкой; исправления выпускаются новым PATCH.
Релиз становится публичным только после загрузки файлов и создания Go-тега.

Для локальной проверки допускается `pwsh tools/package-release.ps1 -Tag v0.0.1`
без существующего тега: это только упаковка в `artifacts/releases`, не публикация.
Python/npm manifests временно меняются при сборке и восстанавливаются в `finally`.
